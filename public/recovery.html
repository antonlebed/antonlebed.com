The recovery chart

The knife edge run backwards: the re-imports that buy the deleted move back, one door to a row, and what each door actually sells.

The machine is the growth apparatus of the Growth section — a tower, a modulus grown one factor at a time, the founding one being the integers modulo the product of the first k primes — and it has two faces; p and q name primes throughout. On the depth face — the growth machine run as a program — the state is a modulus N read as a vector of exponents — each prime p a window carrying the depth vp(N), and a place in the number theorist's sense, the p-adic one — every move multiplies N, and a test reads presence, whether p divides N. On the element face the machine holds registers in Z/N over a set of windows that grows, a window read through its residue being a channel. Its moves are the channel-local ring operations — add, subtract, multiply and write a constant, each acting on every channel separately — the pseudo-inverse, inverting each invertible residue and writing zero where there is no inverse, channel reads, and one global zero-test, the AND of the per-window zero bits; a window adjoined mid-run is born at zero. Base extension, which is row 3's door and not one of those moves, sets a new window from the lift of the others, the integer their residues jointly name, exact while the value the register is meant to hold stays below their product; a window is synced when its residue is that value's. Universality means Minsky's — two counters with increment, decrement and an exact zero-test — and needs a remembering borrow, a move that lowers a counter while a test reads the value it descends through, where a borrow that reads nothing is forgetful; the depth face has none, and the one the construction deleted was the archimedean place — the size of an integer, the one place no prime names — turned into a move, which is what leaves that face one move short (the knife edge). A door is something the construction deleted, re-imported as a primitive: a read in row 1, a move in row 2, an operation in row 3, an outside agent in row 4. What the chart FINDS is that each is priced by the READ it carries, which is why the grading question below asks only that. A read is a ratchet when it flips at most once per run and re-readable when it can be consulted again with a new answer.

The grading question under every row: what does the re-import let the machine read of a value as it moves? The candidate invariant "universal exactly when the value a down-move destroys is read at the archimedean place" is false at the first row, where universality is bought with no size read and no value destroyed. What survives as the currency is a derived down-move, a readable quantity some move lowers while a test reads it, which need not be stored anywhere: it can be synthesized as the difference of two rising ladders, or manufactured natively by a sparse residue under a moving pointer. And the answer splits by face: the depth face's doors of rows 1 and 2 buy possibility, that face's door-free machine being decidable; the element face, over a window set whose moduli are unbounded, is universal with no import, so its doors sell per-step exactness and never possibility.

Row 1: the second ruler

The door: prime-power depth read at two or more places at once, the machine layer of the ruler ladder, which grades arithmetic over addition by how many independent scales its predicates read. The model is the growth machine with tests upgraded from presence reads to three-way depth comparisons sign(α·vp − β·vq − γ), α and β positive integers and γ an offset, so each weighs one depth against another; moves still multiply, depths never fall, nothing archimedean is imported. The price starts at the reads: depth beyond 1 means local rings and not residue fields, so the door re-imports the depth axis the founding tower's squarefree moduli drop.

The purchase is quantized: one comparison buys nothing, two independent comparisons buy everything rule

Every test reading the same form α·vp − β·vq, at any offsets, plus presence reads, makes the machine bisimilar to a one-counter machine, since every move shifts the form by a constant fixed by the move and every test factors through it and through presence bits that flip once, so halting stays decidable (one-counter automata being pushdown automata with a unary stack): the growth machine's monotone decidability proof dies here, a comparison flipping back to false as the depths leapfrog, but the one-counter argument survives. Two independent comparisons, X = v2 − v3 and Y = v3 − v5 with equality reads, run a two-counter Minsky machine exactly, every macro move a multiplication. The borrow is synthesized: no ladder is lowered, but on the derived counter v2 − v3 the move INC3, raising v3 by one, is a value-reading down-move. The macro move that lowers X is INC3 then INC5, the second increment leaving Y where it was: two increments plus a comparison equal one borrow. The threshold is the second independent comparison at any window count from two: across three or more as two differences, and at exactly two as a second ratio on one pair (two ratios). The mirror: exact-configuration reachability stays decidable, monotone runs to a fixed target being bounded, while halting goes undecidable — the exact reverse of reset nets, where reachability is undecidable and termination decidable (Dufourd–Finkel–Schnoebelen 1998) — a reset net keeps a decrement beside its reset, which is why it is not the finite-state corner of row 2.

Scope. The one-comparison bisimulation is proved at every ratio, every move and test factoring through the form, and verified in one run at 1:1 on v2 − v3 over a three-program battery, with one-counter decidability cited; the two-comparison simulation is verified step-exact with Minsky cited. The universality is Minsky's theorem applied to a verified instruction set, never an exhaustive claim over programs.

Two places at two ratios are universal, and the miss was the gadget's rule

At exactly two places the linear route is closed: two monotone depths' moves span a two-generator cone in any linear encoding, at most a half-plane, which cannot carry both directions of two counters. Take windows p, q with tests at the ratios 1:1 and α:β in lowest terms, α > β; the register is the common depth u at home, vp = vq = u. A p-step raises vp by one and a q-step raises vq; a test reads the sign of its form, vp − vq − γ or α·vp − β·vq − γ at each of the finitely many offsets γ the machine is built with, and fires when the form reads zero — a firing halts no program, it is the signal a walk's leg waits for. By the second form's own coefficients a p-step adds α to it and a q-step subtracts β. The one-walk gadget, q-steps from home until the α:β form's sign stops being positive and then p-steps until the 1:1 form fires, multiplies u by α/β only when β | u and lands at ⌈αu/β⌉ otherwise, an affine miss off the multiplicative lattice that destroys any exponent encoding. But a cyclic pattern, a p-steps and b q-steps repeated, lowers the α:β form by the constant Δ = bβ − aα per cycle, so it fires at whichever substep — position inside one cycle — first meets the form's starting value modulo Δ, and the p-steps home land at an affine image of u, one per residue class: a pattern is a generalized-Collatz instruction whose multiplier is chosen. Two such patterns carry everything. The read, which returns a residue class of u and multiplies u by α, and the multiplier, which multiplies u by a chosen rational: each is one cyclic pattern with its a and b solved for the job. The read's cycle is j repetitions of β − 1 p-steps then α − 1 q-steps, so Δ = j(α − β): the q-steps of one repetition visit α − 1 consecutive multiples of α modulo α − β — a q-step subtracts β, and β ≡ α there — which is every residue since gcd(α, α − β) = 1, and the repetitions shift that by α − β each, so the substeps of one cycle meet every residue modulo Δ and the form fires for every u: there is no miss. The substep at which it fires tells the control the class of u mod j, and the home leg lands at α·u plus a constant fixed by that class: j is chosen as the modulus the program wants read, which in the compile below is a fraction's denominator. The multiplier: cycles of a = rβ − sα p-steps and b = α(r − s) q-steps, with Δ = αs(α − β), have q-steps visiting b consecutive multiples of β modulo Δ, every residue once b ≥ Δ with s coprime to β, that is once r/s ≥ α − β + 1 (below that threshold, at 3:2, ×9/5 compiles by luck and ×11/7 does not); so they fire for every u, and on the multiples of s the home leg lands at (r/s)·u plus an integer offset fixed by the firing substep. For the read and the multiplier alike the control zeroes the offset by two finite tables indexed by the substep: a detector test at an offset one Δ above every offset the table names reaches zero at the same substep a whole cycle before any of them, since the form at offset γ + Δ is the form at γ one cycle later, and reports the substep; the walk goes on to the zero of the offset γ = nΔ the table names for that substep, which fires n cycles sooner than offset 0 and so lands n·b lower, and then takes the table's count of extra q-steps, each raising the landing by one. So, once u is large enough for the detector's cycle to exist, the read lands at exactly α·u, a residue read whose only cost is the junk factor α, harmless to any exponent encoding that avoids the primes of α, and u ↦ (r/s)·u exactly when s | u. A FRACTRAN program — a list of fractions, each step multiplying by the first whose denominator divides the register, halting when none does; Turing-complete (Conway) — over primes coprime to αβ, each fraction padded to the threshold by a power of a junk prime, a prime of α, runs as follows: for each fraction in order, read u modulo its denominator, the junk factor absorbed; if the denominator divides u, multiply by the padded fraction and begin the next step, and if not, go on to the next fraction; halt when none applies. A register lifted once at the start by a power of the junk prime past the tables' bounds stays past them, every later step multiplying it by α or by a padded fraction of at least 2. Stripping α's primes leaves the program's own state: Conway's multiplication program, relabelled onto the six primes 5 to 19 and padded, takes 5273 to 116 in 25 steps on two places at 3:2, the trace stripped of 3s equal to the reference interpreter's at every step.

Scope. Each law is proved, and each is checked over its own population: the cone lemma over the 6,016 ordered independent integer form pairs with coefficients in [−4, 4], the read's cyclic pattern at five ratios, the multiplier at 3:2 over eight multipliers above the threshold and five below. The compile is verified step-exact; FRACTRAN universality is cited.

Row 2: the remembering borrow

This row's door is a plain decrement, and it is answered upstream, on the Computation landing. The comparison there is between two machines' only down-move, never between a machine and itself plus a primitive: that decrement beside the native zero-test, the remembering borrow, is exactly Minsky, while a machine whose only down-move is the forgetful borrow — reset, clearing a window and reading nothing on the way down — is a cliff down to finite-state: increment, reset and zero-test are the reset corner (Computation). The row is the chart's calibration: the danger is the reading, not the lowering.

Row 3: the height cut

The door: base extension, at the one point where the tower natively re-imports the archimedean. The ring's error-correcting code is a height cut: its codewords are the elements whose lift lies below D, the product of the data windows, the low primes the value is stored in, so the remaining parity windows are fixed by the data and a check re-derives them (The Object). Ring operations do not preserve the cut, so state evolution must re-derive parity per step, which is base extension. The model is the element machine over a growing squarefree window set, no depth axis, with base extension as the door primitive.

Parity per step is a borrow, and without it the zero-test lies in both directions rule

On elements the down-move x − 1 and the zero-test are both native; what is missing is exactness. A window adjoined mid-run is born at zero rather than at the lift's residue, and the unsynced zero-test reads a false zero at the wrap and a false nonzero from the frozen offset — window 7 born at count 4 holds 3 when the counter truly returns to 0. Base extension is the missing sync: grow-and-extend before each increment keeps every register's lift equal to its counter, and a two-counter machine runs step-exactly, its lift below N through 60 grown increments. The row reduces to row 2: parity per step turns the ring's wrapped subtraction into the remembering borrow, what remembers being the lift certificate: the fact, re-established each step, that the register's lift is still its counter. The freeze lemma prices the offset exactly: a window p born at count c0, when the product of the multipliers by units applied so far was M0, holds (c − (M/M0)·c0) mod p at count c under state-independent adds and unit multipliers — operations the program fixes in advance, never chosen by a branch on the state — M being that product now, so repair from a synced window is exact under the cut and a reset re-syncs at zero alone.

Scope. The simulation is verified step-exact on seeds 0 to 8, its height invariant checked at each of the 60 grown increments above, and both lies exhibited; the freeze formula holds at every step of two SEPARATE batteries, one additive of 300 steps with two mid-run births and one mixed with unit multipliers; Minsky universality cited. With the bare class universal (the frontier rider), what the door sells is per-step exactness, an O(1) lift certificate against the rider's unary time.

The keystone lemma: base extension from a growing source is non-ring-computable, and two codes part on what the dynamics computes rule

Every state-independent composite of ring operations is channel-local by the Chinese remainder theorem, so on a window born with a constant it yields a constant, while the target lift(x) mod p is not constant in x: CRT independence itself forbids the door at that layer, the residue number system's own engineering fact — base extension is the one non-channel-local operation among its arithmetic, the zero-test being the machine's only other cross-window read, and the wrap count is the archimedean bit (Szabó–Tanaka 1967). Scoped honestly, a program can rebuild a lift residue from any source of windows it can name, so bounded-source extension is native; what no fixed program reaches is extension from an unboundedly growing source, the addressing wall: finitely many window names against unboundedly many windows. A syndrome is the read a code checks membership by. Beside the height cut sits the dictionary code of Meaning, whose codewords form a subgroup of the units, a bound word being a coset of it. Lying wholly below the cut does not tell the two codes apart, because such a coset can lie there too: {31, 101} = 31·{1, 101·31−1}, an order-2 coset below D = 210 in Z/2310. What does tell them apart is what the dynamics computes: the height-cut syndrome is the predicate [lift < D], aperiodic and non-ring-computable to re-derive, while the dictionary syndrome is channel-local and survives multiplication by a unit, the move that code runs on. Checking a dictionary codeword is free; re-deriving where the state sits against the height cut is the whole tax. The same fact at the pseudo-inverse: to test whether q divides a count c, q must be one of the windows; to divide by q it must be a unit, which a window's prime is not, so with q a window the pseudo-inverse divides exactly in every other window while writing 0 into window q, which is the quotient's true residue there only when q divides the quotient as well.

Scope. The lemma is proved for state-independent ring-op composites, any polynomial map and any register count, its channel-locality half exhausted over all 2310 elements and the addressing wall argued; the division-sync tension checked on all 42 multiples of q = 5 in Z/210, the 0 written into window q disagreeing with the true quotient residue on the 33 whose quotient is not itself a multiple of 5.

Row 3 without the door: the bare class and its allocator

The frontier rider: the bare element class is universal rule

The door-free element machine — growth, ring operations, channel reads and the zero-test, no base extension — is Turing-universal. The construction is sparse: a counter lives as a residue in one pointed window and as literal 0 everywhere else, the pointer an idempotent register re-seated on the growth frontier at every increment. One increment is one grow, so the pointed prime — the (3 + g)-th after g grows, at least g + 4 — always exceeds the count: the value stays inside the first period of every read that touches it and the zero-test never gets the chance to lie. Born-at-zero, the no-door clause itself, is the encoding's free sync, every unpointed window's intended content being 0. The candidate lemma that once guarded this cell, "periodic reads cannot assemble an aperiodic borrow", is false as stated: a periodic read is exact below its period, and one grow per increment mints periods faster than the count climbs. The rider breaks no wall; it dodges them. Its one read across all windows is the zero-test, no window is ever named, and the keystone lemma is untouched because no lift residue is ever rebuilt: the rider pays time instead.

Scope. Step-exact on the Minsky battery at seeds 0 to 10 and on a 2,000-operation random schedule, machine-checked at every executed step, the construction program-uniform, the pointed prime exceeding the counter's VALUE by at least 6 at every increment of the battery; Minsky cited. A wrap control exhibits the periodic lie the pointer discipline prevents.

The door sells efficiency, never possibility: a quadratic factor, tight for the rider rule

An increment at value v costs v transfer passes, the unary steps that carry the value into the fresh window one unit at a time, so counting one register to T costs T(T − 1)/2 against the door's T, one synced write per increment: bare ≤ door², and the quadratic is tight because that cost is counted and not bounded, a counter's value never exceeding the increments applied to it, so T is the operation count as well as the target. The coarse classes — decidable, P, NP, PSPACE — are closed under a polynomial factor, so the door crosses no class boundary; a quadratic factor is still a real polynomial cost, though no lower bound over all bare programs is proved. Two cost layers stack and only the lower is the door's: the encoding blow-up of a two-counter simulation of a Turing machine (Schroeppel 1972) is inherited equally by door machine and bare rider, and the door removes only the carrier-sync layer. The literature's exponential unary gaps live on other axes — the number of counters (Fischer–Meyer–Rosenberg 1968) or the input encoding's length (Berman 1978) — not the per-operation sync cost of one counter, on the reading of them this row was priced against.

Scope. The price is measured directly, counting to T bare against door; the tightness for the rider is proved, no bare lower bound; the class facts are cited.

The minimal carrier FOR THE RIDER: the borrow is a fresh-register supply rule

The rider runs on the even tower (moduli 4, 6, 8, …: every window composite, every pair sharing a factor, no field, no single-ring CRT reading) and on the successor tower (moduli 2, 3, 4, …, the slowest strictly increasing supply — the sequence of moduli the fresh windows are minted at — whose slack is constant rather than growing, the frontier modulus g + 4 against a count of at most g, minimum headroom exactly 4 over the battery, where the prime tower's minimum of 6 is an early dip — value 1 under prime 7 — that widens after). A supply capped at 8 lies at count exactly 8. So the rider's carrier is an unbounded supply of fresh exact writable finite cyclic registers born at zero, each larger than the count it must hold — a substrate-free fact one level below the founding tower, the prime staircase pn > n being one instance of that condition and not its source. That headroom clause is this construction's requirement and not universality's: the supply law below buys universality on every unbounded supply, registers smaller than the count included, so what is characterised here is the rider's carrier and not the only one. Primality, pairwise coprimality, the field structure, the CRT glue and the pseudo-inverse are all certified unused, the rider making no pseudo-inverse call and no named-window read in any run. The growth machine grows too but never mints a writable fresh register; what growth mints here for universality is exact writable capacity.

Scope. The identical protocol is step-exact on both carriers, and the cap control lies exactly where derived.

The supply law: bounded is finite-state, unbounded is universal rule

Write mg for the modulus of the g-th window minted, the supply as a sequence. At the bit supply, every window Z/2, with the windows reached only through registers — the register marking the newest window, no read naming a window — every operation acts identically on every window's tuple of register bits, and the configuration is (control, the set of tuples some window holds), a sound and complete bisimulation quotient, so the machine is finite-state — a sibling of the growth machine and not a step below it, decidable by boundedness where that one is decidable by monotonicity, its registers resettable; the argument uses only a bounded alphabet, so any supply with mg ≤ C is finite-state under the same addressing restriction. On an unbounded supply the doubling counter keeps its value on one pointed window and, when that window is full, grows until a window of more than twice its modulus appears, found by comparing moduli with residue counters after every grow, then moves the value across in unary; the search ends because the supply is unbounded, so two such counters run faithfully on every unbounded supply, monotone or not, and the machine is universal, Minsky cited. The supply's rate matters for capacity only to a counter that grows one window per increment, whose count after g grows then reaches g. A positional counter keeps its value as digits in several windows, each window's modulus the base of its digit; moving a lower digit to a window of another modulus would change the weight of every digit above it, so only the top digit moves to the fresh window, the product Wd of the lower bases is fixed when the program is written, and the counter holds exactly the values below Wd·mg. On a nondecreasing supply it therefore keeps counting, grown one window per increment, exactly when Wd·mg > g at every g, which some fixed Wd achieves exactly when mg = Ω(g): the supply mg = max(2, ⌈g/3⌉) suffices for a counter whose low digit sits in a starting window of modulus 4, where the single rider, which needs mg > g, wraps.

Scope. Bounded ⇒ finite-state verified through an exact bisimulation quotient on a program battery at window sizes 2, 3, 4. Unbounded ⇒ universal argued from the construction; with the modulus comparison after every grow it counts 0 → 200 → 0 on a supply whose modulus alternates g and 2 and on one large only at powers of two, two counters exact on the alternating one, and 0 → 60 → 0 on mg = max(2, ⌈√g⌉), where the comparison once per block of grows reaches 0 → 2000 → 0. The once-per-increment counter is exhibited uncapped at ⌈g/3⌉.

Row 4: the interactive hand

The fourth row's door is an outside hand pushing the machine between steps, and it buys the basin, where a run lands, never the class: on the depth face, where pushes only multiply and the bare machine's tests are fixed thresholds on depths, every test is a ratchet, so any hand, omniscient or uncomputable, delivers at most one flip per test, so the fate map over all hands factors through a finite branch tree and whether some hand or every hand can make a run halt stays decidable, while on the element face a hand that watches the true values syncs each grown window by one native add and buys what base extension buys. Past the hand, decidability lives at the interface jointly: a universal machine behind f one-shot flags crosses at most f events to a finite-control reader and, through one re-readable register, crosses an event at every step, yet a single flag's timing carries the halting problem into a reader that steps between events with unbounded readable state to count the wait in, and a task scheduler built on these reads alone is a vector addition system, its safety decidable, until a system call turns a wait's timing or an empty channel into a branch: The interface.

One level below the supply law the growing machine has a structure theorem of its own — the window pool is a delay line of the operation stream, holding what the program wrote and nothing else — which reduces deciding halting to certifying that a run grows forever, a certificate scheme discharging that on all but one program of a measured population, and a three-verdict decider, sound on a fragment of programs, whose third verdict hands back a question about the supply's own arithmetic: The delay line.
