The interface

Two settings, one question. The hand, the first section below: an outside hand pushes the growing machine, and we ask whether it can change what the machine computes, or only where its run lands. The read surface, the second: one machine reads another through flags, each able to change once, or through a mailbox, one register the far side overwrites and the reader re-reads at every step; we ask which questions about the far side stay decidable. Each time the answer turns on what the reader is allowed to read, and on whether it can tell WHEN what it read arrived.

Each setting has a boundary, the partition between the two sides, and the second setting names its sides: a core, the machine whose own questions are undecidable, sits behind the boundary, and the bulk is the machine on the reading side, which sees the core only through what the boundary exposes. One change in what is exposed is a boundary event; a flag is a read that can change only once, so the hand can push it past its one change and never again, and a flip is that one change. The flag word is the sequence of exposed values the bulk has read so far, in order and with no times attached, so a reader is flag-word-driven when it cannot tell WHEN an event arrived, only in what order — and a bounded supply of flags bounds what can cross at all. A reader can time an event when it can tell apart unboundedly many arrival times, which takes both a read of the event and unbounded state to count the wait in; a flag-word-driven reader cannot.

The machine is the growth apparatus of the Growth section, grown from the integers modulo a modulus N one factor at a time, and it has two faces; p and q name primes throughout. On the depth face the state is N read as a vector of exponents — each prime p a window carrying the depth vp(N) — every move multiplies N, so depths never fall, and a test reads a read atom, whether a depth has reached a fixed threshold (presence is the threshold 1). On the element face the machine holds registers in Z/N over a set of windows the machine grows when it asks, the modulus squarefree on this face so each window is a prime's residue field, also called a channel: channel-local ring operations, acting on every window separately and aimed at one window by multiplying with a register that is 1 there and 0 elsewhere, channel reads of one window's residue, and one global zero-test, the AND of the per-window zero bits; a window adjoined mid-run is born at zero. The lift of a register over a set of windows is the integer below their product its residues there jointly name, a window is synced when its residue is that of the virtual value, the integer the register is meant to hold, and base extension sets a new window from the lift over the windows born before it, exact while the virtual value stays below their product. Universality means Minsky's: two counters with increment, decrement and an exact zero-test. A machine's class is what it can compute at all, so a purchase that moves the class buys possibility and one that does not buys only speed or exactness. The construction deleted the archimedean place — the size of an integer, the one place no prime names — so no read on either face compares magnitudes, and a door is such a deleted read re-imported as a primitive; the recovery chart prices them: the comparison door, a test comparing two depths, buys the depth face universality, while on the element face the door-free machine is universal already — a counter kept in one window and re-seated at every grow on the newest, larger one, whose modulus always exceeds the count — so the bare class, what that machine computes with no door at all, is everything, and its door, base extension before every step, buys only per-step exactness, every window synced at constant cost, and never possibility. A read is a ratchet when it flips at most once per run and re-readable when it can be consulted unboundedly often with new answers.

The hand

Do pushes from outside — multiplications of the modulus, as every growth move is, or on the element face writes into the registers — change the machine class, or only the basin, the outcome a run lands in: whether it stops, and where its growth settles? The model is the handled machine, the machine plus an external hand applying pushes between steps, graded by the hand's read set: blind, a fixed schedule; machine-grade, the machine's own read kinds; door-grade, anything determining the true virtual value: depth comparisons, lift reads, or full watching since birth. On the depth face the handled machine moves by its program's multiplications and tests only fixed thresholds on depths; a growth law's own choice of move, which reads more than thresholds, is not one of its tests.

Pushes are inert on the depth face: the ratchet law rule

Depths never decrease, so every depth-face read atom flips at most once per run: a program with k atoms receives at most k flips from any hand, omniscient or uncomputable, the map from hands to the machine's control outcomes — whether its program halts, and which control states it passes through — factors through a finite branch tree, since between flips the machine's readable state, its control with every tested depth capped, is finite and tells apart only finitely many flip timings; and both halting games — does some hand, does every hand make it halt — are decidable on the capped-depth quotient, the control state with each depth cut off at the largest threshold a test reads, played as a two-player game. The comparison door cannot be smuggled through move-only pushes: the hand can know the comparison stream and cannot tell it. This ratchet wall is the read-side twin of the recovery chart's addressing wall, finitely many window names against unboundedly many windows: a fixed lexicon of one-shot readables against an unbounded outcome stream.

Scope. The game decider on the capped-depth quotient agrees with exhaustive schedule enumeration over 11,957 runs on four machines, the flip budget never exceeded; on ratchet-only read surfaces this machine's inertness holds for any hand whatsoever.

On the element face the hand's read is the whole purchase rule

Let a machine's control follow a counter program while an omniscient hand keeps the counter and publishes each zero-test's verdict. On the depth face the hand has nothing to publish through but the read atoms, so it spends one flag, a fresh read atom it pushes past, per verdict: with k flags it follows exactly the seeds (starting values) whose runs make at most k tests and stalls at the next, a witness of the wall whose proof for every protocol is the ratchet law. On the element face one re-readable mailbox register, overwritten by the hand with a multiply by zero and an add and read by the machine modulo 2 at every test, carries every verdict and runs every seed. A door-grade hand runs full universality through a door-free machine: the watching hand syncs each grown window by one native add whose parameter carries its knowledge — base extension performed by the intervener, the element face's door with the non-channel-local computation moved into the hand — and, the bare class being universal, it buys what that door buys, O(1) exactness and not possibility. Below the door nothing moves: a blind hand mints no exactness the machine lacks, the freeze lemma — a window born out of sync keeps its offset, its residue minus the virtual value's, fixed by its birth and by the product of the unit multipliers since — holding verbatim under a fixed schedule of external adds to the whole register and multipliers by units, and a finite-state machine-grade hand is absorbed into one product control.

Scope. The flag protocol's stall at flag exhaustion witnessed at k = 2, 4, 8 and the mailbox step-exact; the watching hand's simulation step-exact with Minsky cited; the blind hand checked over three 200-operation schedules and the machine-grade hand absorbed over 120 steps.

The repertoire, graded: basin, not class rule

The intervention repertoire of the inside view — the scar, the extra depth a push writes into the state; healing, a growth law absorbing a push and seating new primes as before; the rudder, a push that steers where growth settles; the phoenix, a push of 2 at each halt — is move-only and class-inert: over the states tested a fresh scar flips exactly one read atom, a deeper second scar none. The basin stays programmable. With λ(N) the Carmichael exponent, the least e with xe ≡ 1 mod N for every unit x, a world is one run from a seed of the law demanding new dynamics, which extends N by the least m ≥ 2 with λ(Nm) > λ(N); the price of deepening a prime is the least m with that property which also raises the prime's depth, a prime's column is the outcome that sends its exponent to infinity, and a world is locked onto a column when no rival move can undercut that price again. A push by a power of 2 that brings the 2-depth to max(3, v2(λ(N)) + 2) leaves v2(λ) at the 2-depth minus 2, and from there the price of deepening 2 is 2 itself at every later step, the least move there is, so any world is one push from 2's column; and one push raising q's depth to vq(λ) + 2, times a prime P whose P − 1 enlarges λ enough to lift every rival prime's price above q, with P ≢ 1 mod q, which Dirichlet's theorem on primes in progressions supplies, steers a world onto a target prime q's column, constructed and checked to q = 13.

Scope. The one-push lock onto 2's column is proved and checked at 200 of 200 states, the steering at 16 of 16 pairs with targets q ≤ 13.

Across the chart's doors and the hand the class is set by the composite read set, machine plus hand, and by what the machine reading it can time, never by who moves or what is pushed: the same read set can give two classes when the reader can time a flag's flip (the flip-timing channel). On the element face possibility was never for sale to the bare class: the element doors, a computable hand's included, are read imports that buy O(1) per-step exactness where the bare machine pays unary time, while an uncomputable hand writing through a re-readable read only relativizes the machine to what the hand knows. The depth face still sells possibility: it is monotone, its native read atoms are ratchets, its bare class stays decidable, and no hand can leak a comparison across a ratchet-read surface to a machine that tells apart only finitely many flip timings. The element face's channel reads are periodic in the register's value and re-readable, and re-readability is the read-side difference.

The read surface

With universality native to the bare element face there is no door to keep thin, and the dividends, what the construction's deletions — the archimedean place above, and on this face the higher powers of each prime a squarefree modulus drops — pay back, split into two layers. The static ones — canonical forms, decidable equivalence, self-certification (the static dividend) — are facts of the ring and stand everywhere. The runtime ones — decidable halting, decidable hand-games — are properties of the interface AND of what the machine behind it can time, with a measured scope.

The composite probe: undecidability confined behind k ratchet flags for a timing-blind reader, crossing at every step through a mailbox, and the toll rule

Couple a flag-word-driven bulk, here with finite control, to a genuinely universal core — a two-counter program on the bare class — through k ratchet flags: at most k boundary events ever cross, every realized history lands on the branch tree, and both boundary-quantified fate questions, whether some or every history of flag events makes the bulk halt, are answered by enumerating the tree with zero core steps, while which leaf the core realizes is the core's own reachability, undecidable across cores. Through a re-readable mailbox the same core's parity crosses at every step: a two-state bulk mirrors it, one boundary event per step, 200 in 200, where the ratchet side's flags allow at most k = 2. Carrying value v into a fresh window by a transfer loop of the machine's own, as the bare class's counter does at every grow, costs exactly v transfer passes, the unary steps that carry a value into a fresh window one unit at a time, t(t − 1)/2 of them over t increments when each increment grows a window, the i-th carrying i − 1, and t(t − 1)/2 + t operations in all, against base extension's one synced write per step: the toll on that route is the value carried, with no lower bound claimed over all bare programs.

Scope. Rule for flag-word-driven bulks, the schedule enumeration exhaustive over four composite moduli, the toll checked at every increment.

The interface conjecture is false: the flip-timing channel theorem

The candidate theorem — any bulk with decidable frozen fate questions behind a ratchet-only boundary keeps boundary-quantified questions decidable — fails: one ratchet flag, one waiting counter and a clocked simulator suffice. The waiting counter transcribes the flip's timing; a budgeted simulation converts it into a halting-witness check; some-halt equals the halting problem while every fate question with the flag held frozen stays decidable. One ratchet flag carries unbounded information, the timing, into any bulk unbounded enough to store it. The confinement results keep their scope: two classes of finite timing resolution, whose run between boundary events passes through finitely many states and so tells apart only finitely many flip timings, finite-control (the ratchet law's branch tree) and flag-word-driven (timing-blind, the composite probe); and, by a move frame and not a read principle, well-structured bulks, monotone over a well-quasi-order — an order on states in which every infinite sequence has some later state above an earlier one — for whether some flag timing reaches an upward-closed target, a set of states closed under moving up that order, their product with the flag words staying well-structured when two configurations are compared only at the same flag word (Finkel–Schnoebelen 2001). The flip-timing channel is one-sided: with the history that never flips among the histories, every-halt stays decidable for a deterministic bulk behind k ratchet flags whose frozen fate questions are decidable uniformly, one procedure for every configuration and flag word, and whose halt is absorbing, since the history raising no further flag must halt on its own and that finite run caps the flip times worth trying, flag by flag; were every flag obliged to flip, the clocked simulator inverted, halting when its budget runs out and looping when the simulation halts, would make every-halt the complement of the halting problem. Well-structured systems carve decidability by monotone moves over a well-quasi-order (Schmitz–Schnoebelen), and safety games are undecidable with both players monotone (Abdulla–Bouajjani–d'Orso 2003). So decidability lives at the interface, jointly: fate questions quantified over every history a ratchet-only boundary can deliver, posed by a finite-control or flag-word-driven machine whose own fate questions are decidable, stay decidable whatever sits behind the boundary, while which history the far side realizes may not be; a boundary exposing a re-readable read can carry everything to a reader that stores it; re-readability alone does not force the loss, a machine whose only down-move is a reset, re-reading a sign, staying finite-state (the forgetful borrow); and the read kinds alone do not close the questions.

Scope. A theorem given Minsky's halting theorem, by an explicit reduction, and every-halt's decider by the capped recursion; the mechanics verified exhaustively at probe scale, 46 checks.

The kernel reading: a scheduler that only waits on these reads is covered by a vector addition system once a task may be delayed a step rule

Build the smallest scheduler and message queue on presence over a fixed enumeration of task slots, the seats: a receive that makes a task wait while its queue is empty (a zero-guard), a residue read of the tick, the count of scheduling rounds run so far, and a one-shot equality on a rung, a tick count reached exactly once. A call is one such read or send a task makes, the workload is the calls the tasks make, and a credit is a token a consumer returns to a producer's queue to license one more send. The module's syntax tree is asserted free of order comparison: 30 equality nodes, one subtraction (the receive's decrement), no less-than and no min. Remove its capacity bounds and the argument runs in four steps. First, the deterministic kernel is not well-structured: the compatibility axiom, that a state holding extra tokens can match every step of the state without them, fails at 22 of 1,600 sampled pairs, every one at a blocked receive, where the larger state passes and the smaller waits. Second, the may-pass relaxation, in which an enabled receive may also wait, the task scheduled later, fails it at 0 of the same 1,600 and, under the schedulers where it is clock-preserving (Scope), contains every deterministic run as its no-delay choice; it is a vector addition system, counters that rise and fall with no branch on zero, over a finite quotient: seat table, position, tick residue and, where a rung is read, whether the tick is before, at or past it. So whatever is not coverable in the relaxation, no state at least as large being reachable, is unreachable in the kernel, and the Karp–Miller tree — finite, built by sending to ω every coordinate a repeatable loop raises — decides coverability. Third, the tree run: on a producer–consumer with three credits circulating on a queue back to the producer, three data tokens are coverable and four are not, and a timer queue, one the tick sends to and no task receives, is unbounded. A capped kernel's data, credits and control run as the uncapped one's until a data or credit drop, since a send advances its task whether or not it drops and no task receives the timer's queue. A data drop is a send onto c queued tokens, which at capacity c of three or more puts c + 1, at least four, in the uncapped run, and a credit drop needs four credits on one queue, where the three credits, held or queued as data or as credit, never number more than three; so the data queue, dropping on full, never drops at capacity three or more, with no comparison anywhere, as the runs print (data drops at capacities 1 and 2, none at 3, 4 and 8, while the undrained timer queue drops at every capacity). Fourth, what the relaxation cannot see: a call escapes it when one more token can change the sequence of control states a task passes through, repeats dropped, and not only its timing. Among the calls the verifier builds, none of the workload's waits does, and three branches do: a try-receive, whose empty branch is a zero test (one tested queue beside untested ones is a vector addition system with one zero test, reachability decidable by Reinhardt 2008 and Bonnet 2011; two reach Minsky machines); a branch on the tick's residue downstream of a wait, the flip-timing channel inside a kernel; and a branch on a rung, which reads that timing once, diverging at 51 of 72 sampled pairs while its rung is ahead and at 0 of 351 past it, where the residue branch diverges at 351 of 351. A residue wait is harmless, a rung wait, a sleep until a tick the task has passed, is a ratchet a late task never leaves, and escaping the relaxation is not losing decidability, as the one tested queue shows. The class landing is the asynchronous-programs theorem (Ganty–Majumdar 2012: a multiset task buffer under a nondeterministic scheduler has safety equal to coverability for Petri nets, vector addition systems drawn as places and transitions, EXPSPACE-complete; with cancel, which resets a handler's pending count, a single test for a pending handler's absence makes it undecidable, while emptiness tests of one fixed handler set without cancel keep it decidable) and its real-time extension (Ganty–Majumdar 2009: a clock that advances only when no zero-delay task is pending simulates zero tests, and safety is undecidable). The kernel has no cancel; what its reading adds is which calls keep the class, and that the clock's residue stays inside the relaxation as a wait and escapes it as a branch.

Scope. Rule at the verifier's scale; the class claims stand on the cited theorems, a kernel on a finite machine being finite-state whatever it compares. With one try-receive the verifier hosts a program halting exactly on even inputs on one queue counter. With a per-round tick the relaxation is clock-preserving, its delay step advancing the tick as the scheduler's own visit would, both under an oblivious round robin, where a blocked task still spends its turn, and under a skipping one, where a blocked task is passed over; a scheduler that skips against a per-step tick is not clock-preserving.
