The clock machine

A machine that can only start clocks, advance them together, nudge the newest one and ask whether they coincide at zero. With one coincidence read per register it runs two counters on every unbounded supply and needs no pointer to an old window; with one read over every register it keeps no memory across a read.

The clock machine runs on a supply mg, the modulus of the g-th window grown, each window a residue ring Z/m. It has r registers, each holding one residue at every window, finite control, and four operations: tick, add ±1 at every window of one register; pulse, add ±1 at the newest window of one register only; grow, append a window born at 0 in every register; and a zero-test, true when every window it reads holds 0. No operation names an older window, so each window runs as a clock of period m and a zero-test reads whether clocks coincide at 0. Write C = lcm(m1, …, mg) over the windows grown. A register is faithful when its value tracks the count of increments applied to it, and the sqrt pole is the supply mg = max(2, ⌈√g⌉). The machine is the growing-window machine of the delay line with multiply, write-constant and register-to-register addition removed, so the saved pointer that the doubling counter keeps is not available. Universality is Minsky's, cited.

The clock counter needs no saved pointer rule

Register A holds V mod m at every window. Then a tick is an increment or a decrement, and the zero-test of A is true exactly when V ≡ 0 mod C, so the counter is faithful below C and its overflow is visible: a true zero-test right after an increment means V + 1 = C. A grow breaks the invariant: the grown window, of modulus m′, is born 0 rather than V mod m′. A second register R, the timer, starting at zero repairs it in 2V steps: tick A down, pulse its newest window back up and tick R up until A tests zero, which holds the new window at 0 while the old ones reach 0 after exactly V steps; then tick R down and A up until R tests zero, which leaves A at V at every window, the new one included. On overflow the counter undoes the increment, grows, runs the round trip and retries, so it grows only at an overflow and reaches N in exactly the least g with C > N; C is at least every modulus, so it is unbounded on every unbounded supply. Two counters sharing one timer run a two-counter machine. Both ingredients carry weight: without the pulse the first loop stops at the least s with s ≡ V mod C0, the lcm before the grow, and s ≡ 0 mod m′, so it hangs when gcd(C0, m′) does not divide V and lands at a wrong value otherwise; without the timer the counter miscounts at 2.

Scope. Rule: the invariant is argued from the construction, and the programs are checked against a second engine that stores every register at every window. Printed with no miscount after any operation: 0 → 20000 → 0 on the sqrt pole in 101 grows, and 65 grows to reach 2000, where the doubling counter spends 9,424,910; 0 → 100 → 0 on mg = max(2, ⌊log2 g⌋ + 1) in 64 grows; 0 → 2000 → 0 on mg = g at even g and 2 at odd g in 18 grows; B := 3A from A = 300, then A := B, ending at (900, 0) on three registers. With every modulus 2 a 104-grow budget runs out at value 1, and without the pulse the round trip hangs at value 1 on the sqrt pole. The zero-test here reads one register at a time; read over every register at once, the machine keeps no memory (one read keeps no memory).

One read keeps no memory rule

Call the run from a true read to the next a trip. At a true read every window holds 0, so the configuration is the control state and the number of windows grown. Every read until the next true one answers false, so the operations of the trip are a lasso u v v v ⋯ fixed by the state it starts in, each copy of v a pass, and the trip ends at the first read on that word that is true, or never. Let v hold a grow, and let every window grown during the loop have modulus above 4|v|. A window born during pass i holds in one register, at a fixed read position in pass k ≥ i + 2, the integer c + (k − i)n, with c fixed by the grow it was born at and n the register's net tick over one pass, its pulses being over by then. A true read in pass k ≥ 4 finds the windows born at one grow in passes k − 3 and k − 2 at 0; their integers are at most 4|v| in size, below their moduli, so both are 0, and they differ by n, so every net tick is 0. With every net tick 0 each window's integer stops moving, and the answer at a read position is the same in every pass from the third on. So the first true read falls in u or by pass 3, and on a supply tending to infinity, once every modulus exceeds a program constant, a trip that ends grows a bounded number of times: a run is a finite automaton reading the supply's arithmetic one way, and whether its halting is decidable rides on that arithmetic. The hypothesis carries weight: with the loop's moduli 2, a four-operation loop ends in pass 500 after 500 grows. The gap to the clock counter is reading one register while another holds a value, the seam counter systems also have: vector addition systems with one zero-tested counter have decidable reachability, and two zero-tested counters give Minsky machines (Reinhardt 2008; Bonnet, Finkel, Leroux and Zeitoun 2012); a joint test of every counter is one test of a counter carrying their sum.

Scope. Rule: argued from the construction. No trip whose loop grows and reads ended past pass 3 over 21,500 random programs of two registers and up to six control states, on mg = g + 1 and the sqrt pole, and over 41,500 lasso-shaped programs; a constructed loop inside the hypothesis ends in pass 3, so the bound is attained; the pass-500 loop, its moduli raised to g + 16, has not ended after 600 passes. Two engines, one storing every residue at every window, agreed on 14,547 reads.
