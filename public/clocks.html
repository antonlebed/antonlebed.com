The clock machine

A machine that can only start clocks, advance them together, nudge the newest one and ask whether they coincide at zero. With one zero-test per register it runs two counters on every unbounded supply and needs no pointer to an old window; with one zero-test over every register a true read leaves only the control state and the number of windows grown; on the supply g + 1 one trip reads whether the next modulus is prime, that trip ending no sooner than the lcm of the moduli grown before it, and chained trips run a finite automaton over the primes.

The clock machine runs on a supply mg, the modulus of the g-th window grown, each window a residue ring Z/m. It has r registers, each holding one residue at every window, finite control, and four operations: tick, add ±1 at every window of one register; pulse, add ±1 at the newest window of one register only; grow, append a window born at 0 in every register; and a zero-test, true when every window it reads holds 0, the windows of one register or of every register as each block below states. Performing one is a read, the word every block below uses. No operation names an older window, so each window runs as a clock of period m and a read tells whether clocks coincide at 0. Write C = lcm(m1, …, mg) over the windows grown. A counter is faithful over a range of values when the value it reports is the net count of increments and decrements applied to it there, and the sqrt pole is the supply mg = max(2, ⌈√g⌉). The machine is the growing-window machine of the delay line with multiply, write-constant and register-to-register addition removed, so the saved pointer that the doubling counter keeps is not available. Universality is Minsky's (Minsky 1967), cited.

The clock counter needs no saved pointer rule

Register A holds the counter's value V as V mod m at every window. Then a tick is an increment or a decrement, and the zero-test of A is true exactly when V ≡ 0 mod C, so the counter is faithful below C and its overflow is visible: a true zero-test right after an increment means V + 1 = C. A grow breaks the invariant: the grown window, of modulus m′, is born 0 rather than V mod m′. A second register R, the timer, starting at zero repairs it in a round trip of 2V steps, V being below C0, the lcm before the grow, as it is at an overflow: tick A down, pulse its newest window back up and tick R up until A tests zero, which holds the new window at 0 while the old ones reach 0 after exactly V steps; then tick R down and A up until R tests zero, which leaves A at V at every window, the new one included. The round trip is base extension, setting a new window to the value the old windows hold, which the recovery chart grants as a single primitive operation and which costs here the 2V steps above. On overflow the counter undoes the increment, grows, runs the round trip and retries, so it grows only at an overflow and reaches a value T in exactly the least g with C > T; C is at least every modulus, so it is unbounded on every unbounded supply. Two counters sharing one timer, each repaired by its own round trip after a grow since a grow misaligns both, run a two-counter machine. Both ingredients carry weight: without the pulse the round trip's first half stops at the least step count that is ≡ V mod C0 and ≡ 0 mod m′, so it hangs when gcd(C0, m′) does not divide V, is right when m′ divides V, and lands at a wrong value otherwise; without the timer, growing at overflow with no round trip, the counter miscounts at 2 on the sqrt pole.

Scope. Rule: the invariant is argued from the construction, and the programs are checked against a second engine that stores every register at every window. Printed with no miscount after any operation: 0 → 20000 → 0 on the sqrt pole in 101 grows, and 65 grows to reach 2000, where the doubling counter spends 9,424,910 grows; 0 → 100 → 0 on mg = max(2, ⌊log2 g⌋ + 1) in 64 grows; 0 → 2000 → 0 on mg = g at even g and 2 at odd g in 18 grows; a second counter register B := 3A from A = 300, then A := B, ending at (900, 0) on three registers. With every modulus 2 a 104-grow budget runs out at value 1, and without the pulse the round trip hangs at value 1 on the sqrt pole. The zero-test here reads one register at a time; read over every register at once, the machine keeps no memory (one read keeps no memory).

One read keeps no memory rule

Under one read over every register, call the run from a true read to the next a trip. At a true read every window holds 0, so the configuration is the control state and the number of windows grown. Every read until the next true one answers false, so the operations of the trip are a lasso u v v v ⋯ fixed by the state it starts in, each copy of v a pass, and the trip ends at the first read on that word that is true, or never. Let v hold a grow, and let every window grown during the loop have modulus above 4|v|, |v| its number of operations. A window born during pass i holds in one register, at a fixed read position in pass k ≥ i + 2, the integer c + (k − i)n, with c fixed by the grow it was born at and the read position, and n the register's net tick over one pass, its pulses being over by then. A true read in pass k ≥ 4 finds the windows born at one grow in passes k − 3 and k − 2 at 0; their integers are at most 4|v| in size, below their moduli, so both are 0, and they differ by n, so every net tick is 0. With every net tick 0 the answer at a read position is the same in every pass from the third on: a window born before the loop holds one integer from pass 2 on, the ticks cancelling over a pass and the pulses reaching only the newest window; a loop window born two or more passes back holds c, fixed by its grow; and the windows born in the last two passes hold integers fixed by their position in v, the same at every pass from the third. An old window is one window holding one integer, so its answer does not move; each loop window's integer is at most 4|v| in size, below every loop modulus, so it reads 0 exactly when it is 0 whichever new modulus it sits under. So the first true read falls in u or by pass 3, and on a supply tending to infinity, not merely unbounded, once every modulus exceeds a constant fixed by the program, a trip that ends grows a bounded number of times, a loop without a grow adding none. So from that point on a run is its finite control walking the number of windows grown upward in bounded steps, each step decided by the supply's moduli up to it, and what one step can read is the subject of one trip reads primality. The hypothesis carries weight: with the loop's moduli 2, a four-operation loop ends in pass 500 after 500 grows. The gap to the clock counter is reading one register while another holds a value. Counter systems split along the same line: vector addition systems with one zero-tested counter have decidable reachability, and two zero-tested counters give Minsky machines (Reinhardt 2008; Bonnet, Finkel, Leroux and Zeitoun 2012). There a test of every counter at once buys nothing, being one test of a counter carrying their sum; that identity needs the counters non-negative, and residues lose it by wrapping — 2 and 3 at a modulus 5 both fail the test while their sum is 0 — so what one read over every register leaves is fixed by the argument above and not by that identity.

Scope. Rule: argued from the construction. No trip whose loop grows and reads ended past pass 3: 1,176 such endings over 21,500 random programs of two registers and up to six control states, on mg = g + 1 and the sqrt pole, a sample not held to the modulus hypothesis, and over 41,500 lasso-shaped programs; a constructed loop inside the hypothesis ends in pass 3, so the bound is attained; the pass-500 loop, its moduli raised to g + 16, has not ended after 600 passes. Two engines, one storing every residue at every window, agreed on 14,547 reads.

One trip reads primality rule

Under one read over every register, take the trip u = grow, v = tick B +1, read, pulse B +1, read, pulse B −1, from a true read after g grows, with C the lcm of the g moduli grown before it and m′ the new modulus. At pass k the old windows hold k and the newest holds k at the first read and k + 1 at the second, so the first read is true when C and m′ divide k, and the second when C divides k and k ≡ −1 mod m′, which is solvable exactly when gcd(C, m′) = 1, at pass C·((−C−1) mod m′), before the first read's pass lcm(C, m′). So the trip ends at its second read exactly when m′ > 1 is coprime to every earlier modulus, and on mg = g + 1, where C = lcm(2, …, g + 1), exactly when g + 2 is prime. Still on that supply, move the pulses and add a third read: v = tick +1, pulse −1, read a, pulse −1, read b, pulse +1, pulse +1, read c, all on B, nine operations with the grow. The newest window holds k − 1, k − 2 and k at the three reads, so c is true at pass lcm(C, m′) always; at a prime p = g + 2 ≥ 3, read a is true at pass C(C−1 mod p) and read b at C(2C−1 mod p), both before Cp, so the trip ends at a exactly when C−1 mod p < p/2. At a composite g + 2 other than 4, reads a and b are never true and the trip ends at c; at 2 it ends at a and at 4 at b. Call the prime's bit 1 when the trip ends at a. The bit is a condition on a residue of the lcm, and no local key tested fixes it: for no L ≤ 40 do p mod L and whether each of p ± 1, p ± 2 is prime, a higher prime power or neither fix it over the primes to 2000 (the primes 19 and 139 agree on that key at L = 40 and differ in the bit).

Scope. Rule: argued for every g, and checked by an exact solver of the trip's congruences at g = 0 to 200, where the first trip ends at its second read at exactly the 46 g with g + 2 prime; a second engine, stepping each window's operations and combining the zero sets by the Chinese remainder theorem, prints the bit at all 302 primes from 3 to 2000, 147 of them 1. On a supply of the first 60 primes, each followed by a planted next modulus that is either a new prime above 104 or 214, the first trip ends at its second read exactly at the new primes, 60 times in 60. The local-key refutation is toy-scale: keys at L ≤ 40 over the primes to 2000.

Chained trips walk the prime word rule

Each ending of the trip in one trip reads primality is a true read one grow later, so the trip can be chained. Give every state s of a deterministic automaton over the letters {first, second}, naming which read ends a trip, its own copy of the trip, send a true read in copy s to the grow of copy δ(s, letter), and let the program halt when control enters the copy of an accepting state. After t trips from no windows the control sits in the copy of the automaton's state on the first t letters, and on the supply g + 1 the letter of trip t is whether t + 1 is prime, so the program halts exactly when the automaton accepts a prefix of the word whose letter at j ≥ 2 is whether j is prime. Whether it does is a sentence of the monadic second-order theory of (N, <, primes), which is decidable if Dickson's conjecture, the linear case of Schinzel's Hypothesis H, holds (Bateman, Jockusch and Woods 1993) and not known to be decidable otherwise (Büchi and Landweber 1969 noted that a decision procedure would in principle settle the twin prime conjecture; Berthé, Karimov, Nieuwveld, Ouaknine, Vahanwala and Worrell 2024). One such program's halting is a named question. Call a window automaton one that remembers the last y letters and halts when they hold a stated number of primes; the one at y = 3159 with threshold 447, reading past j = 2, halts exactly when π(x + 3159) − π(x) > π(3159) = 446 for some x ≥ 2, a failure of the second Hardy–Littlewood conjecture π(x + y) ≤ π(x) + π(y) at y = 3159. An admissible 447-tuple fits in 3159 consecutive integers, so the qualitative prime k-tuple conjecture, which Dickson's implies, makes it halt (the incompatibility of the two conjectures is Hensley and Richards', 1973), and no counterexample to the second Hardy–Littlewood conjecture is known. The nine-operation trip chains the same way over the letters {a, b, c}, adding the primes whose bit is 1 to the theory as a second predicate, and no hypothesis in the role of Dickson's conjecture is cited here for the bit; to 30000, every assignment of the bit to twin primes, to consecutive primes and to the triplets (p, p + 2, p + 6) and (p, p + 4, p + 6) occurs, each assignment's count within 1.63 standard deviations of its binomial mean under a fair independent coin.

Scope. Rule for the reduction, argued; the decidability is cited, and the Hardy–Littlewood instance is argued from the cited tuple, not recomputed. Printed through j = 202: the recorder chain's 201 letters, the automaton that remembers nothing and prints each letter, equal primality; 40 random automata of two to six states run as programs exactly as run on the word; the window automata at y = 2 to 8, reading past j = 2, never halt at π(y) + 1 primes and halt at π(y) exactly where a direct scan does. The claim covers chains of these trips only: a general trip also reads prime-power letters, g modulo constants of the program and residues of the lcm. The bit statistics are toy-scale: four patterns over the primes to 30000.

A trip that reads a gcd with the deep moduli waits out their lcm rule

Under one read over every register, take a trip, the lasso run from a start state at a true read after at least two grows, on any supply, and let m′ > 1 be the modulus of its first grow. Call the windows grown before the trip, all but the last, deep, and C′ the lcm of their moduli. The gcd at issue throughout is gcd(C′, m′), which a trip that ends before growing has no m′ to tell. A pulse reaches only the newest window and a grow only adds a window, so every deep window of a register takes only the ticks and holds one integer X, the ticks since the trip began; they all read 0 exactly when C′ divides X, which needs X = 0 or |X| ≥ C′. At pass k of the loop X = nk + c, with n the register's net tick over a pass and c fixed by the program, and before the loop |X| is bounded by the program; with N the largest |n| (at least 1) and K a program constant above every |c| and every pre-loop |X|, a true read before the pass bound (C′ − K)/N has X = 0 in every register, a condition the program alone fixes. Every other window reads a congruence modulo its own modulus. So whether each read before that pass is true is fixed by the program and the moduli from the last pre-trip window on: two supplies agreeing on those moduli share every ending below the smaller of their two pass bounds, and where the trip ends differently on them it waits its own pass bound on the supply with the smaller one. Any supply has a companion that agrees from its last pre-trip window on, has the other gcd and a larger C′: multiply one deep modulus by a prime factor of m′ when the gcd is 1, and otherwise replace every deep modulus by a distinct prime above C′m′. So a trip that tells the gcd on every supply waits at least (C′ − K)/N passes on each of them: no choice of periods lets a trip that divides by whatever came before do it cheaply. A trip correct on one fixed supply only, such as g + 1, where the deep moduli are fixed by the others, is not bounded by this argument.

Scope. Rule: argued past a constant of the program; the companion construction is argued and not run. Checked by the exact solver on 3,000 random programs whose loops do not grow and whose stems grow at most four times, each run on two supplies that share the last pre-trip modulus and the next four and differ in the deep moduli, each lcm above 106: of the 3,000 pairs, 1,184 ended below both pass bounds and none differed; in each of the 428 whose endings differ, the supply with the smaller bound waited it, the least ratio of pass to bound 1.000000000005, a pass of exactly C′ against a bound of C′ − 2.
